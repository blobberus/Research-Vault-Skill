# 2x <Domain Name>

> **To use:** copy this file, rename it `2x <Domain>.md`, fill in every section, delete the guidance in blockquotes, and add one row to the *Domain overlays* table in `00 Router.md`. That is the whole operation.

An overlay. The protocol still runs; this adds what <domain> specifically requires.

## Framing

> What is this research *for*, in this domain, and what is deliberately out of scope? Any standing caveat the deliverable must carry (e.g. "research, not advice").

## The questions people conflate

> Two to four questions that look like one question in this domain but need different evidence. This is usually the most valuable section — it is where domain expertise actually lives.

## Sources, in order

> The primary sources specific to this domain, ranked. Name actual document types, not categories. What is the equivalent of a filing here? What is reliably D-tier?

## Establish, in order

> The five to eight things that must be nailed down, sequenced. Each one concrete enough to check off.

## Domain-specific traps

> The characteristic ways research in this domain goes wrong. Accounting red flags, vendor-inflated figures, citation drift — every domain has its own version. If you cannot name three, the overlay is not ready.

## Freshness

> How fast do facts decay here? Days, quarters, years? What must be date-stamped aggressively?

## Typical deliverable

> Which form, and which skill builds it.

---

### Keep it thin

An overlay that restates the protocol is worse than no overlay — it dilutes the parts that are actually domain-specific. If a section would be true of all research, it belongs in `01 Protocol/` or `03 Standards/`, not here. Target one page.
